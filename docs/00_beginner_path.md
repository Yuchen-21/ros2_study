# 初学者入口：先跑起来，再一点点看懂

如果你第一次看到 `process`、`thread`、`IPC`、`DDS`、`QoS` 或 `Executor`，这很正常。这些词本来就来自 Linux、网络、并发和 ROS 2 等不同领域，不应该要求你在开始课程前全部掌握。

这份入口只做一件事：让你先建立一个简单、够用的画面，再跑出第一个结果。遇到陌生词时可以随时打开[初学者术语表](00_glossary.md)，也可以先跳过，等实验现象出现后再回来查。

> 第一遍的目标不是“把每句话都看懂”，而是能说出：谁在发送、数据暂时放在哪里、谁在接收。

## 1. 先知道这个仓库在学什么

机器人程序通常不会把所有工作都塞在一个文件里。相机、定位、规划、控制可能分别运行，它们必须互相传数据。

先把整个课程想成下面这件事：

```text
发送程序 A                中间通道                 接收程序 B
产生一条数据  ───────→  暂存、搬运或共享  ───────→  使用这条数据
```

课程会逐渐追问：

1. A 和 B 是同一个程序里的两个线程，还是两个独立进程？
2. 数据是被复制进“中间邮箱”，还是放在双方都能看到的共享区域？
3. 接收方太慢时，发送方会等待、数据会排队，还是旧数据会被丢掉？
4. 数据已经到达后，为什么处理它的 ROS 2 回调函数还没有运行？

Stage 01 先不用 ROS 2，只用普通 Linux/C++ 小程序回答前三类问题。这样后面看到 DDS、QoS 和 Executor 时，它们不再是凭空出现的黑盒。

## 2. 开始前只需要这些

第一阶段不要求安装 ROS 2。你只需要：

- 会打开终端并使用 `cd` 进入本仓库；
- 大致认识 C++ 的变量、函数调用和 `if`/循环；
- 系统中有 `g++`、`cmake` 和 `make`。

先检查环境：

```bash
./tools/check_environment.sh
```

输出中的 `g++`、`cmake` 和 `make` 是默认构建路径所需工具。`strace`、`lsof`、`tcpdump`、ROS 2 等显示 `MISSING` 不会挡住第一次学习，它们是后面的观察工具。

如果你是从仓库外层目录进入的，先执行：

```bash
cd ros2_communication_lab
```

后面所有命令都默认在 `ros2_communication_lab/` 目录运行。

## 3. 约 30 分钟的第一次学习

### 第一步：构建示例

```bash
./scripts/build_stage1.sh
```

这里的“构建”就是把 C++ 源代码变成可以运行的程序。脚本还会自动运行基础测试。最后看到下面这句话，就表示成功：

```text
Stage 01 build and tests passed: ...
```

第一次构建的输出很多，不必逐行理解。先只看最后有没有 `passed`；若失败，再从输出末尾向上找第一条明确的错误。

### 第二步：观察两个线程

```bash
build/stage1/thread_shared_state
```

输出中的具体数字每次可能不同。现在只找四件事：

- 两行的 `pid` 相同：两个线程属于同一个进程；
- 两行的 `tid` 不同：它们是两个独立调度的线程；
- `object_address` 相同：它们能看到同一个对象；
- `final_counter` 等于 `expected`：程序用锁协调了同时修改。

可以先用这个类比理解：两个线程像同一房间的两个人，共用一块白板。两人都能写，但需要约定谁先写。

### 第三步：观察两个进程

```bash
build/stage1/process_memory_isolation
```

现在只看两个现象：

- 父进程和子进程打印的地址文字可能相同；
- 子进程把值改成 `99` 后，父进程看到的仍是 `42`。

地址相同却不是同一个变量，听起来反直觉。暂时把它理解为：两个房间都可以有“1 号抽屉”，抽屉编号相同，不代表是同一个抽屉。Linux 在背后把每个进程看到的地址翻译到各自的内存。

### 第四步：让两个进程通过管道传数据

```bash
build/stage1/pipe_process_a
```

看到 `pipe_rx seq=...` 表示接收程序读到样本，看到 `eof samples=5` 表示发送端已经关闭，接收端确认后面不会再有数据。

管道（pipe）可以想成由 Linux 内核保管的一根有容量的管子：发送方把字节写进去，接收方从另一端读出来。到这里，你已经实际看过“共享同一对象”和“跨进程搬运数据”两条不同路线。

### 第五步：做一次口头复盘

不用背术语，试着补完这三句话：

1. 两个线程像同一房间的人，它们可以 ______。
2. 两个进程像不同房间的人，它们默认不能 ______。
3. pipe 的作用是让 ______ 帮忙在两个进程之间传递字节。

参考答案是“共享同一个对象”“直接使用对方的变量或指针”“Linux 内核”。能够用自己的话表达相同意思也算完成。

## 4. 第一遍该读什么，哪些可以先跳过

文档有意保留工程深度，但不要求一次吃完。建议用三遍学习法：

| 遍数 | 目标 | 每章阅读范围 |
|---|---|---|
| 第一遍：看见现象 | 知道这个机制解决什么问题 | “先记三件事”“生动例子”“动手实验” |
| 第二遍：解释现象 | 能用自己的话说出原因 | “核心理论”“常见坑” |
| 第三遍：寻找证据 | 会用工具验证，而不是只凭猜测 | “如何观察系统”“Source Dive”“面试题” |

第一遍可以放心跳过：

- `strace`、`perf`、`tcpdump` 等观察命令；
- `memory order`、`cache coherence`、`ABI` 等底层细节；
- Source Dive 和面试深挖；
- 暂未实现的 Stage 02～14 正文。

跳过不是放弃。第一次先建立主线，第二次再补细节，通常比卡在第一个陌生词上更有效。

## 6. 后续阶段其实在问什么

后续标题看起来术语很多，但每一阶段都能还原成一个生活化问题。现在只看右栏即可：

| 阶段 | 标题中的术语 | 白话问题 |
|---:|---|---|
| 02 | ROS 2 分层 | 一条消息要经过哪些“部门”，每个部门负责什么？ |
| 03 | DDS / RTPS / Discovery | 没有中央通讯录时，发送者和接收者怎样互相找到？ |
| 04 | Executor / WaitSet | 数据已经到了，谁安排某个线程去处理它？ |
| 05 | QoS | 接收者跟不上时，应该等待、保留、重传还是丢弃？ |
| 06 | 序列化 / Zero Copy | 数据为了传输怎样打包，又被复制了几次？ |
| 07 | Shared-memory transport | 同机的大数据怎样通过共用仓库少搬几次？ |
| 08 | Tracing / Performance | 一条消息慢了，时间具体花在哪一段？ |
| 09 | 多机网络 | 数据跨机器和容器后，可能在哪个路口消失？ |
| 10 | Troubleshooting | 面对“收不到消息”，怎样一层层缩小问题范围？ |
| 11 | 中间件比较 | 不同通信工具各适合什么约束，为什么这样选？ |
| 12 | 源码阅读 | 怎样沿一条调用链找代码，而不是淹没在大仓库里？ |
| 13 | 面试专题 | 怎样把已经理解的机制简洁、准确地讲出来？ |
| 14 | 综合项目 | 怎样把前面的选择、实现、测量和排障连成一个系统？ |

因此，现在不必预习所有缩写。学到对应阶段时，再把右栏的白话问题换成精确术语。

## 7. 六个高频词的最简解释

| 词 | 暂时这样理解就够了 |
|---|---|
| 进程（process） | 一个正在运行、拥有自己资源和内存视图的程序实例 |
| 线程（thread） | 进程里的执行路线；同一进程的线程通常共享数据 |
| IPC | Inter-Process Communication，进程间通信的统称 |
| 内核（kernel） | Linux 的核心管理者，负责进程、内存、文件、网络和硬件 |
| 缓冲区（buffer） | 暂时存放还没被下一方处理的数据的区域 |
| 阻塞（blocking） | 当前操作暂时不能继续，线程停下来等条件满足 |

更多词见[完整术语表](00_glossary.md)。阅读正文时优先理解中文含义，英文保留下来是为了让你以后能看懂代码、日志和官方资料。

## 8. 遇到问题时怎样记录

提问或排查时，提供下面四项通常就够了：

```text
我运行的命令：
输出末尾 20 行：
我原本以为会发生：
我不理解的词或现象：
```

不要只写“运行不了”。命令、末尾错误和预期能帮助快速判断是目录不对、工具没安装、构建失败，还是程序正在正常等待另一个终端。

## 9. 第一次学习完成标准

下面五项能做到三项，就可以继续，不必追求全满：

- [ ] 能说出进程和线程最直观的区别；
- [ ] 能解释为什么另一个进程不能直接使用本进程的普通指针；
- [ ] 能独立构建并运行前三个示例；
- [ ] 知道 pipe/socket 是“搬运数据”，shared memory 是“共同看到一块区域”；
- [ ] 遇到陌生术语时知道先查表、做标记或暂时跳过。

准备好后，从[Stage 01 导读](01_linux_ipc/README.md)继续。课程的完整远景可以以后再看[课程地图](00_course_map.md)和[通信全景图](ros2_communication_big_picture.md)。
